rtlsdr.dll scanner-v4 — драйвер RTL-SDR Blog V4 для сканера (сборка 02.11.2026)
==========================================================================

СТАТУС: собрано и проверено на модели USB и в эмуляторе Windows (Wine), A/B-тест
на реальном RTL-SDR Blog V4 04.11.2026 (перестройка 58 -> 23 мс, PLL всегда захвачен), с тех пор в работе.
На новом ПК всё равно сначала A/B-тест (шаг 2), потом установка.

Что это
-------
Тот же драйвер RTL-SDR Blog (последний коммит aed0ea1, 22.03.2026, с поддержкой V4/V4L)
плюс пять правок:

1-3. Быстрая перестройка из osmocom rtl-sdr 2.0.2/2.0.3 (O. Jowett, S. Q. Khan):
     точный расчёт PLL, пропуск записи регистров без изменений, запись регистров PLL
     одним пакетом. Сохранена правка RTL-SDR Blog «ток VCO на максимум».
4.   Надёжность:
     - новая функция rtlsdr_get_tuner_pll_lock(): сканер узнаёт, что PLL не захвачен
       (штатный драйвер в этом случае возвращает «успех» и пишет только в консоль);
     - если PLL не захватился сразу, драйвер ждёт ещё до 5 x 1 мс (только в этом случае);
     - при ошибке записи по I2C кэш регистров сбрасывается, иначе повтор настройки
       «успешно» оставлял тюнер на старой частоте (найдено на модели, см. ниже);
     - переключение входов V4 (HF/VHF/UHF) запоминается только после успешной записи;
     - rtlsdr_get_build_info(): строка сборки, чтобы видеть, какая DLL загружена.
5.   Кэш I2C repeater: минус 2 USB-обмена на каждую перестройку.

Коды возврата не менялись: pyrtlsdr при ошибке set_center_freq закрывает донгл,
поэтому о незахваченном PLL сообщает отдельная функция, а не ошибка.

Результаты на модели (фиктивный libusb, эмуляция RTL2832U + R828D, source/model)
-----------------------------------------------------------------------------
                                  штатный Blog   + osmocom   scanner-v4
USB-обменов на перестройку            23            11           9
макс. ошибка LO (470-800 МГц)        400 Гц        107 Гц      107 Гц
сбой записи PLL, затем повтор        норма       ОШИБКА 50 МГц  норма
сбой переключения входа, повтор   ОШИБКА (VHF-вход)  ОШИБКА    норма

Оценка времени (наш замер 54,7 мс на перестройку / 23 обмена = 2,38 мс на обмен):
перестройка ~21 мс, плитка ~81 мс вместо 114; 470-1000 МГц ~55 с вместо 78,
30-1766 МГц ~181 с вместо 255 (без учёта расчёта, как в V7). Это ОЦЕНКА, её и
проверяет шаг 2.

Что внутри
----------
x64\  rtlsdr.dll для 64-битного Python + rtl_test, rtl_sdr, rtl_power, rtl_biast, rtl_eeprom
x86\  то же для 32-битного Python
      DLL самодостаточна (libusb 1.0.29 и pthreads внутри), нужны только системные
      KERNEL32 и msvcrt. Драйвер WinUSB (Zadig) остаётся тот же.
dll_ab_test.py   тест «старая DLL против новой» на вашем донгле
source\          патчи, скрипт сборки, модель, лицензии

Шаг 1. Узнать разрядность Python и где лежит текущая DLL
---------------------------------------------------------
  python dll_ab_test.py where

Строка «pyrtlsdr loads: ...» — путь к DLL, которую сейчас использует сканер.
Python 64-bit -> папка x64, 32-bit -> x86.

Шаг 2. A/B-тест (сканер закрыть, донгл с антенной на обычном месте)
--------------------------------------------------------------------
  python dll_ab_test.py ab "ПУТЬ\К\ТЕКУЩЕЙ\rtlsdr.dll" "ПУТЬ\К\x64\rtlsdr.dll"

Около 3 минут на каждую DLL. С ключом --full добавится проход 30-1766 МГц
(ещё ~4 минуты на DLL). Что меряется: время set_center_freq (3 x 427 перестроек),
время скана 470-800 МГц (перестройка + чтение 98 304 отсчётов, как в V7),
спектры на 490/600/700/725/750 МГц (по 5 повторов), установление уровня после
перестройки, статистика PLL.

Прислать мне: ab_results\compare_old_vs_new.txt и оба results_*.json.

Хороший результат: перестройка заметно быстрее, ошибок 0, PLL не захвачен 0 раз,
на пустой полосе 700-750 МГц разница уровней не больше 0,3 дБ.

Дополнительно (по желанию): проверка потерь отсчётов на 2,4 МГц, 60 секунд:
  x64\rtl_test.exe -s 2400000
Остановить Ctrl+C. Строк «lost at least ... bytes» быть не должно.

Шаг 3. Установка (только после хорошего A/B)
--------------------------------------------
1. Закрыть сканер.
2. Текущую DLL (путь из шага 1) переименовать в rtlsdr.dll.blog — это откат.
3. Положить на её место rtlsdr.dll из x64 (или x86).
4. python dll_ab_test.py where — должна появиться строка «build: rtl-sdr-blog aed0ea1 +
   osmocom fast retune ... scanner-v4 ...».
Откат: удалить новую rtlsdr.dll и вернуть старой имя rtlsdr.dll.

Если установлен пакет pyrtlsdrlib, pyrtlsdr берёт DLL из него — where это покажет.

Сам сканер пока не вызывает rtlsdr_get_tuner_pll_lock: это следующий шаг после A/B
(повтор плитки при незахваченном PLL).

Не проверено
------------
- работа на реальном V4 (время, уровни, PLL) — это шаг 2;
- x86-версия запускалась только на совпадение экспортов, не в эмуляторе;
- цифры 51 -> 26 мс из osmocom PR #6 измерены автором не на R828D.
