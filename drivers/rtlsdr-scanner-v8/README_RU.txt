rtlsdr.dll scanner-v8 — драйвер RTL-SDR Blog V4 для сканера (сборка 23.11.2026)
==========================================================================

СТАТУС: собрано и проверено в песочнице (экспорт, импорт, сравнение с v7); проверено
на реальном V4 и Windows 11 23.11.2026 (qa_pc стандартный, qa-kit-9.35: 0 FAIL, полный
скан 31-1766 МГц за 155 с, PLL 0/0, I2C без отказов). С V22.12 — драйвер по умолчанию:
его ставит инструкция, он входит в портативную сборку.

Что это
-------
Тот же код драйвера, что scanner-v7 (rtl-sdr-blog aed0ea1 + патчи 0001-0009, ревизия
5049ecd), но статически собранный с libusb 1.0.30 вместо 1.0.29. В libusb 1.0.30
закрыты две уязвимости разбора USB-дескрипторов (внешний аудит 22.11.2026, B6 / AUD-10):
- CVE-2026-47104 — чтение одного байта за границей в parse_iad_array();
- CVE-2026-23679 — разыменование NULL в parse_interface().
Обе дают только отказ (падение программы) от поддельного или неисправного USB-устройства,
подключённого к этому ПК; утечки данных и выполнения кода нет. Исправление
(libusb 578ab76) входит в тег v1.0.30 (87a5563), проверено по истории git.

Чем отличается от v7
--------------------
- Функции те же: 51 экспорт, имена совпадают; DLL зависит только от KERNEL32 и msvcrt.
- Строка сборки (rtlsdr_get_build_info) заканчивается на
  "... (scanner-v7) + libusb 1.0.30 (scanner-v8) 5049ecd, libusb 1.0.30, ...".
- rtl_test, rtl_sdr, rtl_power, rtl_biast, rtl_eeprom побитно те же, что в v7
  (libusb в них не входит — она внутри DLL).

Сборка: source\build_all.sh (rtl-sdr-blog aed0ea1 + патчи 0001-0009, libusb v1.0.30);
две сборки в разных папках дали побитно одинаковые файлы (source\BUILD_INFO.txt).
Компилятор тот же, что для v7 (mingw-w64 13-win32): утилиты совпали с v7 до бита.

Установка
---------
Сканер закрыт. Из этой папки, тем Python, в котором работает программа:
  python install_dll.py            установить
  python install_dll.py where      какая DLL загружается
  python install_dll.py rollback   вернуть предыдущую (копия <имя>.before-v8, то есть v7)
Ожидается «OK - scanner-v8 installed».

Проверка на донгле
------------------
1. python qa_pc.py --smoke — PC5 «scanner-v8 x64».
2. Стандартный qa_pc.py — 0 FAIL, как с v7.
Если что-то не так: python install_dll.py rollback — вернётся v7.

Модель (source\model)
---------------------
Модель USB работает с кодом драйвера и своей заглушкой libusb, без самой libusb:
для v8 её результаты те же, что у v7 (код драйвера не менялся).
