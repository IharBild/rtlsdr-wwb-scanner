rtlsdr.dll scanner-v5 — драйвер RTL-SDR Blog V4 для сканера (сборка 10.11.2026)
==========================================================================

СТАТУС: собрано и проверено на модели USB (сбои I2C, ASan/UBSan) и в эмуляторе Windows
(Wine: загрузка, build info, rtl_test). На реальном V4 ещё НЕ проверено — проверка
после установки (шаг 3).

Что это
-------
scanner-v4 (с 04.11.2026 у вас в работе) плюс одна правка:

6. Повтор передач I2C в тюнер. На вашем V4 запись в тюнер время от времени
   получает LIBUSB_ERROR_PIPE («r82xx_write: i2c wr failed=-9»): при закрытии после
   каждого полного скана, в калибровке шагов и особенно в gain_survey (58 переключений
   усиления на плитку: после ~11 минут сбой примерно каждые 40 с). pyrtlsdr после
   любой ошибки закрывает донгл, поэтому Python повторить не может.
   Теперь драйвер сам повторяет неудачную передачу до 3 раз (пауза 1, 2, 3 мс),
   перед повтором заново включает I2C repeater (если неудача оставила его в
   неверном состоянии). Новая функция rtlsdr_get_i2c_stats(): сколько передач
   повторено и сколько не прошло и после повторов. Сканер (V20.6) печатает в конце
   скана «tuner I2C: N transfer(s) retried, M failed after retries».
   Без сбоев драйвер работает как scanner-v4: тот же 9 USB-обменов на перестройку.

Результаты на модели (source/model, фиктивный libusb с отказами I2C)
--------------------------------------------------------------------
T1 сбой записи PLL          scanner-v4: ошибка, повтор вручную   scanner-v5: проходит с 1-й попытки
T2 сбой переключения входа  scanner-v4: ошибка, повтор вручную   scanner-v5: проходит с 1-й попытки
T3 два сбоя подряд          scanner-v5: перестройка проходит, LO точный, повторов 2
T4 тюнер молчит совсем      scanner-v5: возвращает ошибку (как раньше), потом снова работает
T5 repeater «потерян»       scanner-v5: восстанавливается, усиление и частота ставятся
Обменов на перестройку без сбоев: 9 (как scanner-v4). ASan/UBSan: замечаний нет.

Что внутри
----------
x64\  rtlsdr.dll для 64-битного Python + rtl_test, rtl_sdr, rtl_power, rtl_biast, rtl_eeprom
      (самодостаточна: libusb 1.0.29 и pthreads внутри, нужны только KERNEL32 и msvcrt;
      драйвер WinUSB/Zadig тот же). 32-битной сборки в этот раз нет (у вас 64-битный Python).
install_dll.py   установка / проверка / откат
source\          патчи 0001-0006, скрипт сборки, модель, лицензии

Шаг 1. Установка (сканер ЗАКРЫТ, донгл можно не отключать)
-----------------------------------------------------------
  python install_dll.py

Скрипт сам находит DLL, которую загружает pyrtlsdr (у вас
...\Python37\Scripts\librtlsdr.dll), делает копию <имя>.before-v5, кладёт новую и
проверяет: «build: ... scanner-v4 + i2c retry (scanner-v5) ...», «OK - scanner-v5 installed».

Шаг 2. Откат (если что-то не так)
----------------------------------
  python install_dll.py rollback

Шаг 3. Проверка на донгле
-------------------------
1. Запустить сканер: в консоли «rtlsdr library: ... scanner-v5 ...».
2. Полный скан 30-1766: в конце «tuner I2C: N transfer(s) retried, 0 failed after retries»,
   при закрытии больше не должно быть «i2c wr failed».
3. Главная проверка: python gain_survey.py --antenna (qa-kit) — раньше остановился после
   10 ошибок; теперь должен пройти все 435 плиток. В конце строка «tuner I2C: ...»
   покажет, сколько сбоев драйвер исправил сам.

Не проверено
------------
- на реальном V4: помогает ли повтор (если тюнер после сбоя не отвечает и 6 мс, ошибка
  останется — тогда это видно в «failed after retries»);
- причина сбоев I2C не известна (нагрев, питание USB, логика RTL2832U); повтор её не
  устраняет, только обходит.
