rtlsdr.dll scanner-v6 — драйвер RTL-SDR Blog V4 для сканера (сборка 12.11.2026)
==========================================================================

СТАТУС: собрано, проверено на модели USB (ASan/UBSan) и в эмуляторе Windows (Wine:
загрузка, build info, новые функции, rtl_test). На реальном V4 ещё НЕ проверено —
проверка после установки (шаг 3). Предыдущая сборка scanner-v5 проверена на вашем V4
(сканы 11–12.11, gain_survey 12.11).

Что это
-------
scanner-v5 плюс правки по аудиту драйвера 12.11.2026 (claude/audit-dll-2026-11-12.md).
В обычной работе (без сбоев) драйвер делает то же, что v5: те же 9 USB-обменов на
перестройку, та же точность частоты. Изменены только пути отказа.

7. Восстановление тюнера после повтора I2C (аудит, п. 1 и 5).
   Если передача в тюнер прошла только со 2–4-й попытки, тюнер мог за это время
   сброситься (например, просадка питания USB). Тогда в чипе заводские регистры, а
   v5 считал их верными и дальше пропускал «лишние» записи: усиление, фильтры и
   вход оставались неверными до переоткрытия донгла, без сообщения.
   Теперь после такой передачи драйвер переписывает все регистры тюнера из своей
   копии (5 обменов I2C, как при открытии), повторяет чтение и заново проверяет
   захват PLL. В консоли: «r82xx: tuner registers restored (N since open)».
   После окончательно неудачной записи следующая запись тоже переписывает все
   регистры; если она прошла, пропуск лишних записей снова работает (в v5 —
   только после переоткрытия, перестройка шла медленнее до конца сеанса).
   Новая функция rtlsdr_get_tuner_restores(dev, &n): сколько раз это случилось.

   Выдернутый донгл (аудит, п. 3). При LIBUSB_ERROR_NO_DEVICE повторов нет, все
   следующие передачи в тюнер сразу возвращают ошибку, строка «i2c wr failed»
   печатается один раз. Ошибки, кроме PIPE (IO, TIMEOUT — так выдёргивание может
   выглядеть на Windows), повторяются, только если сам RTL2832U ещё отвечает.
   Ошибка PIPE (ваш случай) повторяется точно так же, как в v5.
   Поправка к аудиту: там написано «44 попытки при закрытии». На модели при
   выдернутом донгле v5 делал 4 попытки (закрытие останавливается на первой
   неудачной записи), v6 — 0 или 1.

8. Тайм-аут чтения отсчётов (аудит, п. 2).
   rtlsdr_read_sync() в исходном драйвере ждёт без ограничения: зависший USB
   блокировал вызов навсегда, программа обходила это потоком с ожиданием до 40 с,
   а повисший поток мешал переоткрыть донгл. Теперь вызов возвращает
   LIBUSB_ERROR_TIMEOUT (-7) через 2 с плюс удвоенное время чтения при текущей
   частоте дискретизации (2400 кГц, 81920 отсчётов: 2,07 с). pyrtlsdr после ошибки
   закрывает донгл, сканер открывает его снова и продолжает (как при других
   ошибках USB, V20.4). Асинхронное чтение не изменено.
   rtlsdr_set_sync_read_timeout(dev, ms): -1 автоматически (по умолчанию),
   0 — ждать всегда (как в исходном драйвере), > 0 — фиксированный.

Сборка (аудит, п. 7): source\build_all.sh собирает всё из исходников с
закреплёнными версиями (rtl-sdr-blog aed0ea1, libusb v1.0.29 = коммит 15a7ebb);
две сборки в разных папках дали побитно одинаковые DLL и программы
(source\BUILD_INFO.txt). DLL по-прежнему не подписана, только x64.

Что внутри
----------
x64\  rtlsdr.dll для 64-битного Python + rtl_test, rtl_sdr, rtl_power, rtl_biast, rtl_eeprom
      (самодостаточна: libusb 1.0.29 и pthreads внутри, нужны только KERNEL32 и msvcrt;
      драйвер WinUSB/Zadig тот же). 43 функции: 41 из v5 + 2 новые.
install_dll.py   установка / проверка / откат
source\          патчи 0001-0008, build_all.sh, build_win.sh, BUILD_INFO.txt, модель, лицензии

Шаг 1. Установка (сканер ЗАКРЫТ)
--------------------------------
  python install_dll.py

Скрипт находит DLL, которую загружает pyrtlsdr (у вас ...\Python37\Scripts\librtlsdr.dll),
делает копию <имя>.before-v6 (это будет ваша v5), кладёт новую и проверяет:
«build: ... (scanner-v6) ...», «OK - scanner-v6 installed».

Шаг 2. Откат (если что-то не так)
----------------------------------
  python install_dll.py rollback      -> вернётся scanner-v5

Шаг 3. Проверка на донгле
-------------------------
1. Запустить сканер: в консоли «rtlsdr library: ... (scanner-v6) ...».
2. Полный скан 30-1766 — время и уровни как с v5 (перестройка ~21 мс, 0 поздних PLL).
3. python gain_survey.py --antenna (qa-kit): должен пройти все плитки, как с v5. Если
   были повторы I2C, после каждого в консоли строка «r82xx: tuner registers restored»,
   уровни после неё не должны отличаться от соседних плиток.
4. Выдернуть донгл посреди скана: сообщение сканера как раньше, строк «i2c wr failed»
   не больше одной-двух, закрытие без задержки.
5. qa_pc.py: PC5 должен показать «scanner-v6 x64».

Не проверено
------------
- на реальном V4: всё выше — только модель и Wine;
- сбрасывается ли тюнер на самом деле при ваших сбоях I2C — неизвестно; если нет,
  перезапись просто повторяет те же значения: 7 обменов USB на случай (5 записей +
  проверка PLL), около 17 мс по оценке 2,38 мс на обмен, не измерено;
- как Windows сообщает о выдернутом донгле (NO_DEVICE или IO) — по документации
  libusb, не проверено;
- тайм-аут чтения на зависшем USB: на модели; программа после ошибки переоткрывает
  донгл (V20.4), это проверено на выдёргивании донгла 11.11.
